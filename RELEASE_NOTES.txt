Camden's Pain(t)  Version 0.5.0  -  10/14/2026
=============================================

Sprint 5 submission for CS 250.

Source code:
  GitHub repo:  https://github.com/CamdenGoddard/Paint
  Tag / release:  v0.5.0  (https://github.com/CamdenGoddard/Paint/releases/tag/v0.5.0)
  This tag matches the code uploaded in the sprint 5 zip.

New features:
  * Unit tests: 23 JUnit tests in src/test/java (run them with "mvn test",
    or right-click the test folder in IntelliJ and choose Run Tests). They
    cover the star/polygon geometry (GeometryTest), the autosave countdown
    (AutosaveTimerTest), saving in other formats (ImageFormatsTest) and the
    web server (ImageWebServerTest).
  * Star with a variable number of points: pick the Star tool, set "Star
    points" (4 to 100), and drag out a box. 4 points is a diamond; 5 and up
    are stars. The first point is straight up.
  * Autosave: tick "Autosave every", pick how many seconds (5 to 3600), and
    every tab with unsaved changes is saved when the countdown ends. A tab
    that already has a file is saved to that file. A tab that was never
    saved gets a backup copy in the PaintAutosave folder in your home folder
    (and stays marked unsaved). A tab in the middle of a mouse drag is
    skipped until the next round. It runs on the JavaFX timeline, once a
    second, so no extra threads are needed.
  * The countdown is optional: tick "Show countdown" to see "Next autosave
    in m:ss". The label next to it shows when the last autosave happened.
    Saving by hand (Save or Save As) restarts the countdown.
  * Web server: tick "Web server on port" (default 8080), tick "Share this
    tab" on each tab you want to show, then open http://localhost:8080/ in a
    browser. The page shows every shared tab, reloads itself every 5
    seconds, and shows a message instead when no tab is shared. Only this
    computer can connect.
  * Saving in another format: Save As can write PNG, JPEG or BMP, whatever
    the picture started as. If the new format could lose something (JPEG:
    lossy and no transparency; BMP: no transparency) a warning explains what,
    says so specifically when the picture has see-through areas, and lets you
    cancel. How this is proven is in TEST_PLAN.md.

Design notes / assumptions:
  * The new logic is in small classes of its own: Geometry (corner math),
    AutosaveTimer (the countdown), ImageWebServer (the server) and
    ImageFormats (saving and the warning text), so each can be unit tested
    without opening a window.
  * Save As now adds the selected filter's extension when the typed name has
    none (or one that isn't PNG/JPG/BMP), so the file name matches what is in it.
  * Pictures are now saved with a transparent background, so see-through
    areas of an opened PNG stay see-through when saved as PNG. Before this
    they were flattened onto white.
  * The web server asks the JavaFX thread for each picture, so you always
    see what is on screen, including edits not yet saved.

Known issues:
  * The web server is local only and has no password; stop it when you are
    done with it.
  * Autosave to a JPEG file re-compresses it each time, which slowly
    degrades the picture. Use PNG for pictures you edit a lot.
  * The selection can only be a rectangle, and text can't be edited or
    moved once it has been placed (use Undo and place it again).
  * Text uses the default font only.
  * Undo history is lost when a tab is closed or reset.
  * The color-name label only recognizes a curated list of common colors;
    anything else reads as "Custom" rather than the closest match.
