Camden's Pain(t)  Version 0.6.0  -  10/26/2026
=============================================

Sprint 6 submission for CS 250.

Source code:
  GitHub repo:  https://github.com/CamdenGoddard/Paint
  Tag / release:  v0.6.0  (https://github.com/CamdenGoddard/Paint/releases/tag/v0.6.0)
  This tag matches the code uploaded in the sprint 6 zip.

New features:
  * Rotate and mirror. Image > Whole Canvas turns the picture 90, 180 or 270
    degrees clockwise, or mirrors it (Flip Horizontal swaps left and right,
    Flip Vertical swaps top and bottom). Image > Selection does the same to
    just the selected piece, turning it around its own center; the piece
    stays floating so it can be dragged into place. Each is one undo step, and
    undoing a 90/270 rotation also puts the canvas size back.
  * Icon buttons. Every drawing tool has an icon button (the Tool drop-down
    is still there and stays in step with them), and New, Open, Save, Undo,
    Redo, the five rotate/flip actions and Clear have icon-and-label buttons.
    The rotate/flip buttons act on the selection if there is one, otherwise on
    the whole canvas. Icons are drawn from vector paths, so no image files
    are needed.
  * Tooltips on every button and toolbar control (rest the mouse on it).
  * Keyboard shortcuts for the menu actions: Ctrl+N/O/S, Ctrl+Shift+S,
    Ctrl+W, Ctrl+Z/Y, Ctrl+X/C/V, Ctrl+A (select all), Ctrl+Shift+C (clear),
    and for the whole canvas Ctrl+R (rotate 90), Ctrl+Shift+R (180), Ctrl+L
    (270), Ctrl+H (flip horizontal), Ctrl+Shift+H (flip vertical).
  * Notifications from the operating system (the corner of the screen on
    Windows) when autosave runs and when it is switched on or off. The
    "Notifications" box turns them on and off. If the computer has no system
    tray the program carries on without them; the autosave status text still
    shows what happened.
  * Threaded logging. What you do is written, one event per line, to
    PaintLog/paint-log.txt in your home folder (Help > Show Log File Location
    shows the exact path). Lines look like:
        10/26/2026 [cat.png] 11:33:03 Line tool selected
        10/26/2026 [new tab] 11:33:06 Rectangle drawn from (10,10) to (90,60), color #FF0000, width 6
    It logs tools, colors, widths and other settings, every shape, stroke and
    piece of text with its coordinates, selections, cut/copy/paste, undo/redo,
    rotate/flip, menu and button clicks, tab changes, open/save/save as,
    format-change warnings, autosave, and the web server. A separate
    background thread (ActionLogger) does the writing: the program only drops
    each line in a queue, so drawing never waits for the disk, and the lines
    are written out in order when the program closes.

Design notes / assumptions:
  * Rotating and mirroring is done on the pixels themselves (ImageTransforms)
    rather than with a display transform, so what you save is what you see.
  * The activity log is a plain append-only text file and is never cleared by
    the program.
  * 38 unit tests now (src/test/java): the new ImageTransformsTest and
    ActionLoggerTest join the geometry, autosave, format and web server tests.

Known issues:
  * The icons for the 90, 180 and 270 degree buttons are the same; the text
    beside each one tells them apart.
  * The log grows without limit; delete the file if it gets big.
  * Operating-system notifications need a system tray; they have only been
    tried on Windows.
  * Rotating a selection by 90 or 270 degrees can push a piece partly off the
    edge of the canvas, which crops it when it is put down.

Sprint 5 features (still in the program):
  * Unit tests: 23 JUnit tests in src/test/java (run them with "mvn test",
    or right-click the test folder in IntelliJ and choose Run Tests). They
    cover the star/polygon geometry (GeometryTest), the autosave countdown
    (AutosaveTimerTest), saving in other formats (ImageFormatsTest) and the
    web server (ImageWebServerTest).
  * Star with a variable number of points: pick the Star tool, set "Star
    points" (4 to 100), and drag out a box. 4 points is a diamond; 5 and up
    are stars. The first point is straight up.
  * Autosave: tick "Autosave every", pick how many seconds (5 to 3600), and
    every tab with unsaved changes is saved when the countdown ends. A tab
    that already has a file is saved to that file. A tab that was never
    saved gets a backup copy in the PaintAutosave folder in your home folder
    (and stays marked unsaved). A tab in the middle of a mouse drag is
    skipped until the next round. It runs on the JavaFX timeline, once a
    second, so no extra threads are needed.
  * The countdown is optional: tick "Show countdown" to see "Next autosave
    in m:ss". The label next to it shows when the last autosave happened.
    Saving by hand (Save or Save As) restarts the countdown.
  * Web server: tick "Web server on port" (default 8080), tick "Share this
    tab" on each tab you want to show, then open http://localhost:8080/ in a
    browser. The page shows every shared tab, reloads itself every 5
    seconds, and shows a message instead when no tab is shared. Only this
    computer can connect.
  * Saving in another format: Save As can write PNG, JPEG or BMP, whatever
    the picture started as. If the new format could lose something (JPEG:
    lossy and no transparency; BMP: no transparency) a warning explains what,
    says so specifically when the picture has see-through areas, and lets you
    cancel. How this is proven is in TEST_PLAN.md.

Known issues from earlier sprints:
  * The web server is local only and has no password; stop it when you are
    done with it.
  * Autosave to a JPEG file re-compresses it each time, which slowly
    degrades the picture. Use PNG for pictures you edit a lot.
  * The selection can only be a rectangle, and text can't be edited or
    moved once it has been placed (use Undo and place it again).
  * Text uses the default font only.
  * Undo history is lost when a tab is closed or reset.
  * The color-name label only recognizes a curated list of common colors;
    anything else reads as "Custom" rather than the closest match.
